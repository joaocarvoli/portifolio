Tripod speech pipeline

OBT Lab (YWAM Kansas City) · Dec 2025 – present
PyTorchXEUSHiFi-GAN v2BPE16 kHz
Problem

Communities with oral-only languages needed a way to produce and check translated speech with no writing system to lean on, and no existing model knew their language.

Built

A text-free pipeline end to end: an XEUS-based acoustic tokenizer with a vocabulary of 100 discrete units, a BPE motif tokenizer over those units, a pitch-conditioned HiFi-GAN v2 unit vocoder at 16 kHz, and Tripod Lab, the experiment-tracking and training dashboard with staged quality gates that decides what moves forward.

Result

A working speech-to-units-to-speech loop, pilots with Terena and Sateré-Mawé speakers, and a method the linguistics lead could turn into specifications and tickets for the rest of the team.

Internalization Room

OBT Lab · LLM agents in a screen-text-free room
Claude APIFlutterTTSSSELLM judge
Problem

Walk a translation team through a passage by voice alone, with an AI guide that helps without taking over, and a way to prove each prompt or model change did not make it worse.

Built

Guide and Validator roles on Claude with explicit tool boundaries, text-to-speech and server-sent events inside a Flutter room with no on-screen text; plus the evaluation harness: a fixed set of golden sessions replayed and scored by an LLM judge, per-role cost accounting and budget gates wired in as the release gate.

Result

Prompt and model changes ship only after the harness passes, with cost per session known before release. The same harness runs a regression suite over the agents' tool use.

One backend, five field products

OBT Lab · platform and apps
FastAPISQLAlchemyPostgreSQLCloud RunAlembicReact
Problem

Five products (Internalization Room, Facilitator Desk, Sound Necklace, Oral Collector, Annotation Studio) built by a small team, each needing auth, storage, access rules and secrets, without five backends.

Built

A shared FastAPI, SQLAlchemy and PostgreSQL backend on Google Cloud Run with authentication, app-scoped access control, Alembic migrations and Secret Manager; the Oral Collector Flutter app for monolingual audio capture on iOS, Android and web; and the React/TypeScript consoles (Tripod Console, Meaning Map UI, Annotation Studio for layer-wise studies of XEUS).

Result

One codebase the whole lab deploys from, with a multi-agent development workflow (isolated worktrees, dedicated reviewers, Linear) that lets two or three engineers ship like a larger team.

How I work

Habits from shipping models to people who cannot file a bug report in writing.

Evaluation is the release gate

A prompt or model change is a code change. It ships when the golden sessions pass and the cost per session is known, not when it looks good in a demo.

Test first, then the feature

Backends and apps grow behind tests; migrations are proven by snapshot, upgrade and downgrade before they touch a database with field data.

Specs the whole team can read

I turn a linguist's method into specifications, tickets and acceptance criteria, and review the engineers' work against them.

Agents as teammates, with a human on the decisions

Isolated worktrees, one reviewer per task, and a decision inbox so the people decide only what the ticket and the docs do not settle.
